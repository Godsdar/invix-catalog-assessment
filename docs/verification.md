# Проверка реализации

Дата: 20 октября 2026. Локальный стенд: Docker, Linux arm64 containers.

## Автоматические проверки

- `npm run build` и `npm run typecheck`: успешно, Next.js 16.4.2.
- `docker compose --profile test run --rm tests`: **15 passed**. PostgreSQL 17 и MinIO настоящие; для внешних вызовов Telegram в этих тестах используется подставной gateway. БД `catalog_test` и bucket `catalog-test` отделены от приложения.
- GitHub CI первоначального решения и версии со скриптами временного HTTPS-запуска завершился успешно.
- MinIO собран из закреплённого официального upstream commit; init создаёт bucket и схему. API readiness возвращает 200.
- Запущены по две реплики API, Next.js, webhook и worker. После остановки одной реплики каждой роли 10 последовательных проверок страницы, API readiness и защиты webhook прошли: 200 / 200 / 403 соответственно.

Интеграционные тесты охватывают создание товара, API-выдачу фотографии, разграничение прав, повторные updates, восемь конкурирующих обработчиков, сохранение диалога, пагинацию и повтор обработки после сбоя между S3 и PostgreSQL.

## Живой Telegram и HTTPS

Создан и подключён настоящий бот `@godsdar_invix_catalog_bot`; webhook зарегистрирован на публичном HTTPS URL из README. Telegram Bot API подтвердил адрес webhook, нулевую очередь и отсутствие ошибок.

- Настоящий `/start` владельца дошёл через Telegram webhook, обработан воркером; ответ «У меня есть товар» отправлен через Telegram. Владелец настроен администратором в локальном `.env` и получил меню с «Создать товар» и кнопкой Mini App.
- Каталог открылся внутри установленного Telegram для macOS как Mini App; заголовок и пустое состояние прочитаны из его webview.
- Для проверки фото создано нейтральное тестовое изображение и отправлено владельцу через настоящий Telegram Bot API. Полученный реальный `file_id` использован в двух явно тестовых updates `/create` и photo+caption, введённых через локальный аутентифицированный webhook. Рабочие воркеры скачали фото из Telegram, сохранили JPEG в MinIO и товар в PostgreSQL. API вернул фото (12 620 байт), публичная страница показала «Демонстрационная кружка» и изображение.

Последний сценарий использует fixture updates: он не выдаётся за ручную отправку фото человеком. Скачивание из Telegram, хранение и выдача изображения проверены на настоящих адаптерах. На живом стенде работают по две реплики каждого компонента приложения.

## Условия доступности

Временный HTTPS-туннель доступен, пока включены компьютер, Docker и контейнер туннеля; его адрес может измениться при пересоздании. Для постоянного размещения нужен сервер со стабильным доменом. Профиль временного стенда отключает автоматический перезапуск после перезагрузки Docker/компьютера. Пробуждение и включение компьютера не настраивались. Секреты находятся только в игнорируемом локальном `.env`.
